## Persistence contract

`SqlAlchemyAgentControlPlaneRepository.commit(write=...)` owns one SQLAlchemy transaction over the run, approval, immutable scope, aggregate sequence cursor, command receipt, ordered domain events, outbox event projections, and queue enqueue-intent rows. The repository only returns `applied` after every requested event, outbox row, and queue intent is flushed in the same transaction. A write error rolls back all of them. Identical command replay returns the stored result and does not insert another event/intent; a changed digest conflicts. Replay rechecks current tenant, employee, company membership, cabinet access, project visibility/assignment, and project state before returning the stored result. A deleted session is tolerated only for a receipt-backed replay or an already-created run transition, preserving the original session linkage without treating the missing session as a new run's authorization. Aggregate cursor updates compare both expected sequence and expected status. Approval decisions persist the authenticated actor in the approval row and event provenance.

Every authorization row used by this check is locked in the write transaction where the database supports row locks. Revoking membership, cabinet assignment/grant, restricted-project assignment, or changing the project/cabinet state therefore cannot race a positive write past the check. Company admins retain the existing restricted-project visibility bypass, but still need current company membership and cabinet access.

Run/approval model rows remain owned by `models/agent_control_plane.py` (the pre-existing model module). New cursor/receipt/event/outbox/enqueue tables are in the exclusive `persistence/agent_control_plane/` zone. Do not add a second declaration for `agent_runs` or `approval_requests`; the wiring gate checks their unique declarations in the existing owner. The dedicated enqueue-intent table is a transactional handoff, not a broker claim that dispatch has happened.
