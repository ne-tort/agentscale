# M04–M06 execution readiness matrix

Статус: migration-stage execution readiness matrix, только документация. Baseline: 2026-11-01.

Документ задаёт bounded readiness для четырёх execution slices: M04.e definition/version foundation, M04 scope registry, M05 plugin instance/runtime fencing и M06 canonical grants/gateway adapter. Это не Alembic revision, не ORM/application implementation и не разрешение shared-environment DDL, backfill, positive writes или cutover. Нумерация M04/M05/M06 здесь обозначает bounded implementation domains; исполняемые revisions должны образовать одну линейную цепочку от актуального repository head.

## 1. Общий порядок и policy

| Slice | Upstream dependency | Read owner до cutover | Write owner до gate | Positive-write status |
|---|---|---|---|---|
| M04 scope registry | aligned tenant type, retained tenant anchors, cabinet/project compatibility and membership proof | legacy owner state plus registry evidence | registry backfill job | запрещена, plugin branch deferred |
| M04.e definition/version | retained tenant and active typed parent scope evidence; inventory and deletion boundary complete | legacy definitions/versions | migration evidence job | запрещена |
| M05 plugin instance/runtime | M04.e keys and active typed scope | legacy instance/runtime plus shadow resolution | fenced instance/runtime path for eligible staged rows | запрещена до M05 gate |
| M06 grants/gateway | M04.e + scope registry + M05 exact instance key/FK | legacy grant decision | legacy writer; adapter mapping/audit/quarantine only | canonical allow запрещён до partition gate |

Cross-slice order is strict: M04 typed parent registry (tenant/cabinet/project) and its validation/backfill -> M04.e definition/version foundation -> M05 exact instance key/runtime fencing and reciprocal registry FK -> M06 canonical grants/gateway. Mapping, quarantine and append-only audit foundations are created before any canonical import; they do not reorder the parent/definition/instance dependencies. A later slice may be prepared in parallel only when its DDL is empty/staged and it cannot enable positive reads or writes ahead of this order.

Общий partition: `(tenant_id, app_definition_id)`, с возможным сужением до scope или exact plugin instance. Один незрелый partition не блокирует уже принятые независимые partitions и не может продвинуться по исключению.

Общие обязательства для каждого slice:

- authority выводится server-side из authenticated context; `company_id`, tenant, scope, subject и instance из запроса являются только assertions;
- source mapping идемпотентен по стабильному `(source_kind, source_id, schema_version)`; `source_payload_digest` сравнивается отдельно, а изменившийся digest — conflict/quarantine, не overwrite;
- backfill resumable, bounded transaction per source row, с checkpoint, digest, reason code и redacted audit;
- archived/quarantined evidence не участвует в ordinary authorization и не считается positive parity;
- `ON DELETE CASCADE` для owner/security evidence не допускается; используется `RESTRICT` или явная archive policy;
- acceptance checks записываются, но во время migration verification freeze не исполняются.

## 3. Cross-slice execution evidence and promotion rule

A slice is `ready for implementation` only when its prerequisites, planned files/ports/repositories, revision slices and static acceptance evidence are reviewed. It is `ready for backfill` only when DDL constraints/RLS are installed in the implementation branch and its source inventory is deterministic. It is `ready for positive write` only when the slice-specific gate and all upstream gates pass atomically; documentation readiness never grants that permission.

For a candidate M06 partition, the minimum promotion record is an immutable, append-only cutover evidence record keyed to the partition `(tenant_id, app_definition_id)` (optionally narrowed by scope/instance). It must retain the source snapshot/schema version, source and canonical/binding digests, final-delta checkpoint, gate evidence, fencing epoch, current writer generation, decision owner, actor and timestamp; it is not inferred from a live status flag:

```text
M04 scope: exactly one active typed scope + parent compatibility proof
M04.e: retained tenant + definition/version owner and immutable artifact proof
M05: exact instance composite key/FK + artifact/subject/session + current generations
M06 schema: canonical checks/FKs/indexes/RLS/FORCE/trusted audit writer
backfill: zero unknown mappings and zero unresolved positive bindings
parity: zero unexplained mismatches, final delta checkpoint recorded
fencing: legacy writer drained; exactly one current writer generation
cutover: canonical read owner and legacy read-only projection
```

Any missing item produces deny, quarantine or explicit system failure and no promotion record authorizing cutover. A known deny, expired/revoked row or approved quarantine is retained evidence, not positive parity. Cleanup of legacy tables is outside M04–M06 and requires a later retention and audit-replay decision.

## 4. Verification freeze

Для этой documentation-only задачи tests, build, lint, format, compile, Alembic execution, migration execution и git checks намеренно не запускались. Код, ORM, gateway, adapter, core docs, shared environments and running databases не изменялись. Backfill, positive canonical writes, cutover, cleanup and rollback drills не выполнялись. Verification remains frozen until the migration is implemented and reviewed multiple times, followed by an explicit decision to lift the freeze.
