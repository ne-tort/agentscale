## Жёсткие правила этой фазы

1. **Verification freeze.** НЕ запускай тесты (`pytest`, `vitest`), сборки (`pnpm build`, `tsc`),
   компиляцию, линтеры, форматтеры, `alembic upgrade`, DDL к живой БД, git-команды
   (`git status/diff/add/commit/push`). Приёмка пишется как артефакты и проверяется рассуждением
   по коду и контрактам.
2. **Разрешённая интроспекция.** Чтение файлов через нативные инструменты, `grep`/`glob`, и
   read-only `python -c "..."` для импорта моделей/схем и печати metadata (без записи в БД,
   без миграций). Это не считается verification.
3. **Файловые операции — только нативными инструментами** (`read`/`write`/`edit`/`glob`/`grep`),
   не через shell (`cat`, `sed`, heredoc). Кириллица в shell-выводе ломается.
4. **Своя зона.** Редактируй только файлы из своей зоны. Чужие зоны можно читать, но не менять.
   Нужен интерфейс вне зоны — зафиксируй blocker в отчёте, не выходи за границу.
5. **Не отменяй и не «чисти» изменения других агентов** (никаких `git checkout`, удаления
   незнакомых файлов, перезаписи общих файлов целиком).
6. **Fail-closed по умолчанию.** Негативные пути (нет контекста тенанта, чужая область,
   устаревшая генерация, неизвестный исход провайдера) должны отказывать, а не деградировать.
   Никаких in-memory заглушек в продакшн-пути.
7. **Идемпотентность и детерминизм.** Повторный запуск с тем же ключом/дайджестом возвращает
   исходный результат; изменённый дайджест — конфликт, а не перезапись.
8. **Секреты и сырые payload в audit/quarantine не попадают** — только redacted reason code.

## Финальный отчёт — обязателен всегда

По завершении (или при невозможности завершить) **отправь отчёт родительскому агенту через
`send_message`** и никуда больше. Обычный финальный ответ в чате отчётом не считается.
Отчёт содержит:

- Task ID и статус (`done` / `partial` / `blocked`);
- что изучено (файлы/контракты) и что изменено;
- полный список затронутых файлов;
- принятые архитектурные решения и их обоснование;
- приёмочные артефакты (что именно покрыто, включая негативные/граничные случаи);
- нерешённые риски и блокеры (с точной причиной);
- явное подтверждение, что тесты/сборки/линт/компиляция/git-проверки намеренно не запускались.

Отчёт обязателен даже если ты ничего не изменил или задача заблокирована. Не заканчивай работу
молча.
