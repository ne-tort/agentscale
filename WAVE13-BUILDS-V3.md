# WAVE13 — «Готовые сборки» v3: устройства-комплекты, «Состав» как контракт, сплит объёмов, количество связи

Продолжение WAVE12 (карточки + матрица совместимости + связи). Развитие модели
по UX-ревизии.

## Виды сборок

`build_kind`: `pc` / `server` (по компонентам) + `laptop` / `nettop` /
`monoblock` / `phone` (**устройства-комплекты**: один слот самого устройства,
комплектующих нет; требования к характеристикам выбирают модель из карточек
типа). Новые типы: `etype_laptop` (ОЗУ/накопитель/экран/батарея/CPU),
`etype_nettop`, `etype_monoblock`, `etype_phone` (память/ОЗУ/экран/камера/
аккумулятор — «SSD считать за память телефона»). `build_scope` типа =
вид сборки.

## «Состав» как контракт (не от балды)

Подстраница `ready_build_spec` (ссылка «Состав» сразу после названия) — поля с
выбором ИЗ ГРУПП типа: Сокет, DDR версия, RAM гб, SSD гб, HDD гб, Питание вт,
GPU гб, Формфактор, Водянка да/нет. Каждое поле пишет `constraints` слота
(готовой сборки) → меняет подбор карточек. Никакого свободного текста. Корпус
и охлаждение обязательны в ПК (резолвер пишет замечание, если слота нет).

## Сплит объёмов (комбинаторика)

Требование ОЗУ/накопителя — СУММА (`ram_total` / `storage_total`), без «×2».
Резолвер раскладывает на модули: «32 ГБ» = 1×32 | 2×16 | 4×8 — выбирается
дешевейший вариант, `qty` слота переписывается фактическим. То же для дисков.

## Слоты на странице сборки

`ready_build_slots_table` — таблица прямо на `ready_build_settings`: тип,
требования, количество (редактируемое у ОЗУ/накопителей), разрешённый
компонент (клик → замена из альтернатив, если есть; иначе некликабельно),
цена, сумма. Ручная замена = закреплённая `card_id` (автоподбор по «лучшей
цене» её не переопределяет; лидер по поставщикам партномера — всё ещё
автоматический).

## Целевой коридор цены (виджет)

`target_price_range` — одно поле «от/до» + справа зелёным коридор возможных
комбинаций (`price_min`/`price_max`), без пояснений. Убраны `price_note`,
`slots_count`, `qty_total`, `unresolved_count`, `is_enabled`, `compat_ok`;
`note`/`compat_issues` — только непустые, warning-тоном сразу после названия.

## Количество сборки в заказе

`equipment_builds.qty` — сколько таких сборок заказано. Масштабирует ВСЕ
компоненты: бюджет `qty = позиция × сборки`, закупка `= бюджет × слот`.
«2 плашки ОЗУ + заказ на 2 сборки = 4 планки».

## MCP / промпты

`BUILD_KINDS` расширен; `equipment_types_list`/`ready_builds_list` знают
устройства-комплекты; `equipment_builds_upsert`/`ready_build_attach` принимают
`qty`. Промпты: `60-builds.md` — виды, обязательные корпус+кулер, сплит
тоталов, GPU/HDD только по явному запросу; AGENTS.md — модульная точка входа.

(новые device-типы) + принудительное обновление промптов.
