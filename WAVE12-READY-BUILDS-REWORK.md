# WAVE12 — «Готовые сборки» v2: карточки, матрица совместимости, глобальные связи

Переработка каталога сборок (заменяет модель WAVE11: группы совместимости,
пул, классы, копии в чат).

## Что убрано

- `build_groups` / `build_group_items` (группы совместимости и пул) — удалены.
- `budget_tier`, `class_key`, `class_signature`, `is_cheapest_in_class` — классовая
  система убрана; несравнимое не конкурирует через `constraints` слотов.
- `equipment_items` («Характеристики оборудования») — легаси ручных сборок чата.
- Копирование готовой сборки в чат (`source_ready_build_id`, редактор слотов в
  чате, `build_slots`-виджет) — заменено глобальной связью.

## Модель v2

### Типы комплектующих — шаблоны (`equipment_types`)

`fields_json` описывает характеристику: `kind` (`text` | `enum` | `groups`),
`required`, `compat_domain` (`socket` / `ram_type` / `form_factor`),
`values` (enum) / `groups` (`{value, label}` — «диапазоны» вида «512 ГБ»).
Значения характеристик — только из заранее заданных групп, не свободные строки.

### Карточки комплектующих (`part_cards`, chats=all)

Партномер (+ `aliases_pn` / `aliases_hash`) + `type_id` + `attrs` (значения из
групп типа; все `required`-поля обязательны — по ним работает совместимость).
Пайплайн резолвит лидер-цену карточки (`best_price`/`best_seller`/`in_stock`/
`offers_count`) батч-запросом в OpenSearch.

### Матрица совместимости

Автоматическая, из `compat_domain`: поля разных типов с одним доменом обязаны
совпадать в сборке (CPU.socket = MB.socket = Cooling.socket; MB.ram_type =
RAM.ram_type; MB.form_factor = Case.form_factor). При подборе слота кандидаты
сужаются до согласованных с уже зафиксированными значениями доменов; конфликты
не блокируют сборку, а пишутся в `compat_ok`/`compat_issues` (грубой
совместимости достаточно).

### Готовые сборки (`ready_builds` + `ready_build_slots`, chats=all)

Слот = `type_id` + `constraints` ({поле: значение группы}) + `qty` +
опционально закреплённая `card_id` (ручная замена из альтернатив слота).
Пайплайн подбирает дешевейшую подходящую карточку; `price_min`/`price_max` —
коридор возможных комбинаций из текущих кандидатов. `target_price_min`/
`target_price_max` на сборке включают умный перебор (~25 паттернов: all-cheapest,
all-priciest, покомпонентные апгрейды, жадные проходы к коридору) — выбирается
максимально наполненная комбинация ≤ max / дешевейшая ≥ min; недостижимый
коридор честно помечается `price_note`. Пересчёт — при записи, кнопкой
«Обновить цены» и по beat-расписанию (дрейф цен/пропажа компонента/смена
лидера отслеживаются сами).

### Связи заказ↔сборка (`equipment_builds`, chats=current)

Строка = **глобальная ссылка** (`ready_build_id`), не копия. Пайплайн чата
зеркалит слоты готовой сборки в `found_groups` (owner_kind=build, ключи
разрешённых карточек) при каждом прогоне — изменение каталога доезжает до
заказа, бюджета и закупки автоматически. Удаление готовой сборки снимает
связи во всех чатах (битая ссылка удаляется зеркалом).

## MCP 3.0.0

Убраны: `ready_builds_catalog`, `build_group_upsert`, `build_group_item_upsert`;
`found_groups_upsert` — только позиции (слоты ведёт платформа);
`equipment_builds_upsert` — только связь (`ready_build_id` обязателен).
Новые: `part_cards_list` (фильтры type_id + constraints), `part_card_upsert`
(валидация по шаблону типа: required + значения из групп), `part_card_delete`,
`ready_builds_list` (компактный, с коридором цен и spec_summary),
`ready_build_get` (сборка + слоты). `ready_build_upsert` принимает слоты
`{type_id, constraints, qty, card_id}` и **сохраняет идентичность слотов**
(патч по row_id или переиспользование по типу) — зеркала чатов стабильны.
`ready_build_slot_upsert` — точечная правка одного слота.

## UI

- Управление: «Типы комплектующих» (редактор шаблона с группами/доменами),
  «Карточки комплектующих» (список + карточка), «Готовые сборки» — сразу
  плоский список с inline «Добавить сборку».
- Слот сборки: `constraints` — выбор из групп типа (виджет `constraint_attrs`),
  ручная замена — пикер карточек `part_cards_pick` (фильтр по типу слота +
  покрытию требований, `row_matches_context_map`), лидеры цен на карточках.
- «Сборка» в Данных: связь (выбор готовой сборки через `ready_builds_pick`),
  переход в каталог по `links.row_id_from_field`.

## Миграция 2026101401

Данные старой модели удаляются (семантика несовместима): build_groups /
build_group_items / ready_builds / ready_build_slots / equipment_items /
equipment_builds + их зеркала групп/офферов/бюджета. Сид-шаблоны типов
обновляются до fields_json с группами; системные промпты (AGENTS.md + правила)
переписаны под новые инструменты и обновляются принудительно (старые ссылки на
build_group_*/class_key сбивали бы агента).
